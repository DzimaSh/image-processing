# Тэхнічная спецыфікацыя Лаб. 3: Сістэма сціскання відарысаў L2L на аснове блокава-лесвічнай структурнай параметрызацыі

## 1. Уводзіны

Традыцыйныя сістэмы сціскання відарысаў (напрыклад, JPEG) па сваёй сутнасці з'яўляюцца сістэмамі са стратамі, паколькі яны прымяняюць квантаванне да каэфіцыентаў ДКП, што прыводзіць да незваротных страт высокачастотнай інфармацыі. Каб дасягнуць аднаўлення без страт, прыводзіцца выкарыстоўваць асобныя алгарытмы, якія звычайна маюць значна меншую ступень сціскання.

У гэтай лабараторнай работе рэалізуецца **сістэма сціскання відарысаў «без страт / са стратамі» (L2L - Lossless-to-Lossy)** на аснове **блокава-лесвічнай (ліфтынгавай) структурнай параметрызацыі** двухвымерных пераўтварэнняў ДКП-ОДКП. Сістэма L2L аб'ядноўвае рэжымы са стратамі і без страт у адзіны канвеер апрацоўкі:

1.  **Рэжым са стратамі (без SIB-блока):** Сціскае відарыс з выкарыстаннем стандартных блокавых пераўтварэнняў. Аднак з-за наяўнасці ўцечкі пастаяннай складнікам (DC leakage) у фільтрах адваротнага ДКП (страта ўласцівасці рэгулярнасці першага роду ва ўсіх каналах, акрамя першага), рэканструяваны відарыс мае характэрны арцефакт у выглядзе **«шахматнай доскі»**.
2.  **Рэжым без страт (з SIB-блокам):** Дзякуючы назапашванню памылак акруглення і квантавання ў ітэрацыйнай паслядоўнасці станаў, ствараецца фінальны блок стану, який называецца **дадатковым інфармацыйным блокам (SIB - Side Information Block)**. Перадача гэтага адзінага блока ($s_K$) у якасці службовай інфармацыі дазваляе дэкодэру цалкам інвертаваць усе прамежкавыя крокі акруглення, забяспечваючы **рэканструкцыю без страт** (PSNR = $\infty$ дБ, MSE = 0) з мінімальнымі накладнымі выдаткамі.

## 2. Блокава-Лесвічная Параметрызацыя (Схема Ліфтынгу)

Сістэма L2L прадстаўляе 2D ДКП ($C_{2D}$) і 2D ОДКП ($D_{2D}$) праз 4-стадыйную структуру блокавага ліфтынгу. Відарыс разбіваецца на піксельныя блокі памерам $M \times M$ ($M=8$), якія не перакрываюцца, у растравым парадку.

Няхай:
*   $x_n$ — $n$-ы ўваходны прасторавы блок пікселяў.
*   $y_n$ — $n$-ы выхадны блок каэфіцыентаў пераўтварэння.
*   $s_n$ — блок стану пасля апрацоўкі блока $n$ ($s_{-1} = \mathbf{0}$).

Двухвымерныя блокавыя пераўтварэнні вызначаюцца як:
*   $C_{2D}(X) = \mathbf{C} \cdot X \cdot \mathbf{C}^T$ (Прамое 2D ДКП)
*   $D_{2D}(X) = \mathbf{D} \cdot X \cdot \mathbf{D}^T$ (Адваротнае 2D ОДКП, дзе $\mathbf{D} = \mathbf{C}^T$)

### 2.1 Крокі прамога пераўтварэння (Кадэр)

Для кожнага блока $n = 0, 1, \dots, K-1$:

1.  **Стадыя 1:**
    $$u_1 = x_n - \text{round}\left( D_{2D}(s_{n-1}) \right)$$
2.  **Стадыя 2:**
    $$u_2 = s_{n-1} + \text{round}\left( C_{2D}(u_1) - u_1 \right)$$
3.  **Стадыя 3:**
    $$y_n = u_1 + u_2$$
4.  **Стадыя 4 (Абнаўленне стану):**
    $$s_n = u_2 + \text{round}\left( D_{2D}(y_n) - y_n \right)$$

### 2.2 Крокі адваротнага пераўтварэння (Дэкодэр)

Дэкадаванне адбываецца ў адваротным парадку ад $n = K-1$ да $0$:

1.  **Адваротная стадыя 4:**
    $$u_2 = s_n - \text{round}\left( D_{2D}(y_n) - y_n \right)$$
2.  **Адваротная стадыя 3:**
    $$u_1 = y_n - u_2$$
3.  **Адваротная стадыя 2:**
    $$s_{n-1} = u_2 - \text{round}\left( C_{2D}(u_1) - u_1 \right)$$
4.  **Адваротная стадыя 1:**
    $$x_n = u_1 + \text{round}\left( D_{2D}(s_{n-1}) \right)$$

> [!IMPORTANT]
> *   У **рэжыме без страт** дэкодэр ініцыялізуе ланцужок станаў з $s_{K-1} = s_K - \text{round}(D_{2D}(y_{K-1}) - y_{K-1})$, дзе $s_K$ — перададзены SIB-блок.
> *   У **рэжыме са стратамі** SIB-блок ігнаруецца, а фінальны стан прымаецца роўным нулю ($s_K = \mathbf{0}$).

## 3. Спецыфікацыя Арыфметыкі з Фіксаванай Коскай

Каб забяспечыць поўную бітавую адпаведнасць паміж праграмнай мадэллю і апаратнай рэалізацыяй, выкарыстоўваецца **12-бітнае прадстаўленне з фіксаванай коскай (фармат Q1.10)**:

*   **Агульная даўжыня слова:** 12 біт.
*   **Цэлая частка:** 2 біты (1 знакавы біт, 1 біт цэлай часткі).
*   **Дробная частка:** 10 біт.
*   **Дынамічны дыяпазон:** $[-2.0, 2.0)$ з крокам $2^{-10} \approx 0.00097656$.
*   **Рэжым квантавання:** Акругленне да найбліжэйшага цотнага (Convergent Rounding / `AP_RND_CONV`).
*   **Рэжым перапаўнення:** Усячэнне (`AP_TRN`).

Каб пазбегнуць прамежкавых перапаўненняў пры множанні матрыц, акумуляванне выконваецца ў больш шырокім **32-бітным акумулятары**, пасля чаго вынік прыводзіцца да 12-бітнага тыпу `coeff_t`.

## 4. Апаратная Архітэктура (Vivado HLS)

Апаратны паскаральнік рэалізаваны на мове C++ у асяроддзі Vivado HLS і складаецца з наступных асноўных модуляў:

### 4.1 Сігналы інтэрфейсу
Верхнеўзроўневы працэсар [fwd_ladder_step_hls](file:///d:/Labs/master/image_processing/hardware/src/l2l_transform.cpp#L94) апрацоўвае адзін крок:
*   `x_n`: Уваходны прасторавы блок пікселяў ($8 \times 8$).
*   `s_prev`: Уваходны стан ланцужка ($8 \times 8$).
*   `y_n`: Выхадны блок каэфіцыентаў ($8 \times 8$).
*   `s_n`: Выхадны абноўлены стан ($8 \times 8$).

### 4.2 Прагмы аптымізацыі HLS
Каб забяспечыць максімальную прапускную здольнасць, выкарыстоўваюцца наступныя дырэктывы:

1.  **Падзел масіваў (Array Partitioning):**
    ```cpp
    #pragma HLS ARRAY_PARTITION variable=in complete dim=1
    ```
    Гэта разразае блокавыя матрыцы па радках, дазваляючы рабіць паралельнае чытанне/запіс за адзін такт.
2.  **Разгортванне цыклаў (Loop Unrolling):**
    ```cpp
    #pragma HLS UNROLL
    ```
    Прымяняецца для паралельнага вылічэння скалярных здабыткаў у множанні матрыц.
3.  **Канвеерызацыя (Pipelining):**
    ```cpp
    #pragma HLS PIPELINE II=1
    ```
    Дазваляе выконваць цыклы з інтэрвалам ініцыялізацыі $II=1$ такт.
