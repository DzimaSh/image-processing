# Тэхнічная спецыфікацыя: Сістэма сціскання відарысаў L2L на аснове блокава-лесвічнай структурнай параметрызацыі

## 1. Тэарэтычныя асновы

### 1.1 Канцэпцыя L2L (Lossless-to-Lossy)
Традыцыйныя сістэмы кадаваня відарысаў падзяляюць сцісканне са стратамі (напрыклад, JPEG, які выкарыстоўвае ДКП з квантаваннем) і сцісканне без страт (напрыклад, JPEG-LS, PNG, якія выкарыстоўваюць прагназавальныя схемы). 
Сістэмы тыпу «без страт / са стратамі» (L2L - Lossless-to-Lossy) на аснове адзінай параметрызацыі дазваляюць праводзіць прагрэсіўнае дэкадаванне ад моцна сціснутага відарыса са стратамі да поўнага біт-эквівалентнага аднаўлення без страт з аднаго і таго ж бітавага патоку.

### 1.2 Рэгулярнасць першага роду і ўцечка пастаяннага складніка (Эфект «шахматнай доскі»)
Эфект «шахматнай доскі» (сеткавы арцефакт) з'яўляецца тыповым скажэннем у блокавых сістэмах трансфармацыйнага кадавання пры працы ў рэжыме са стратамі.

Банк фільтраў (або ядро пераўтварэння) задавальняе **ўмове рэгулярнасці першага роду (першага парадку)**, калі значэнні амплітудна-частотных характарыстык усіх канальных фільтраў, акрамя першага (канала нулявой частаты / DC), роўныя нулю на нулявой частаце:
$$H_k(\omega)\Big|_{\omega=0} = 0 \quad \text{для } k = 1, 2, \dots, M-1$$

У стандартным двухвымерным пераўтварэнні ДКП-ОДКП:
*   Матрыца прамога ДКП $\mathbf{C}$ канцэнтруе сярэднюю энергію блока ў каэфіцыенце нулявой частаты (DC) $y[0,0]$.
*   Сіннтэзуючыя фільтры (слупкі матрыцы ОДКП $\mathbf{D}$) з'яўляюцца артаганальнымі і прадстаўляюць пераменныя (AC) частоты, інтэграл якіх роўны нулю.

Аднак пры рэалізацыі гэтых пераўтварэнняў з **канечнай дакладнасцю** (арыфметыка з фіксаванай коскай) унутры блокава-лесвічнай ліфтынгавай структуры на кожным кроку ліфтынгу ўзнікаюць памылкі акруглення. Паколькі аперацыі акруглення з'яўляюцца нелінейнымі, яны генеруюць шум акруглення, які змяшчае пастаянны складнік (DC), што пранікае ва ўсе высокачастотныя субпалосы.

З-за таго, што субпалосныя фільтры губляюць уласцівасць рэгулярнасці першага роду ў параметрычнай лесвічнай рэалізацыі, гэтая пранікшая энергія пастаяннага складніка выклікае ў прасторавай вобласці структураваны **арцефакт у выглядзе «шахматнай доскі»** (сеткі) на рэканструяваным відарысе.

### 1.3 Выкарыстанне дадатковага інфармацыйнага SIB-блока
Каб ліквідаваць гэты эфект і дасягнуць перфектыўнага аднаўлення, выкарыстоўваецца **дадатковы інфармацыйны блок (SIB - Side Information Block)**.

Пры прамым пераўтварэнні блокавыя памылкі акруглення паслядоўна назапашваюцца ў ланцужку станаў $s_n$:
$$s_n = u_2 + \text{round}\left( D_{2D}(y_n) - y_n \right)$$
дзе $s_{-1} = \mathbf{0}$.

Пасля апрацоўкі ўсіх $K$ блокаў відарыса апошні блок стану $s_K$ (які і з'яўляецца SIB) змяшчае ўсю гісторыю памылак.
*   У **рэжыме без страт** гэты блок $s_K$ перадаецца дэкодэру. Дэкодэр выкарыстоўвае яго для разліку ланцужка станаў у адваротным кірунку, што дазваляе дакладна скасаваць усе крокі акруглення і аднавіць зыходныя пікселі біт-у-біт (PSNR = $\infty$ дБ, MSE = 0).
*   У **рэжыме са стратамі** SIB-блок ігнаруецца (прымаецца $s_K = \mathbf{0}$). Гэта прыводзіць да звычайнага аднаўлення са стратамі з наяўнасцю шахматнай сеткі, што дазваляе параўноўваць якасць выяваў.

## 2. Матэматычнае апісанне

Няхай двухвымерныя аперацыі ДКП і ОДКП вызначаюцца як:
*   $C_{2D}(X) = \mathbf{C} \cdot X \cdot \mathbf{C}^T$
*   $D_{2D}(X) = \mathbf{D} \cdot X \cdot \mathbf{D}^T$ (дзе $\mathbf{D} = \mathbf{C}^T$)

### 2.1 Прамое блокава-лесвічнае пераўтварэнне (Кадэр)
Для кожнага блока $n = 0, 1, \dots, K-1$:
1.  $$u_1 = x_n - \text{round}\left( D_{2D}(s_{n-1}) \right)$$
2.  $$u_2 = s_{n-1} + \text{round}\left( C_{2D}(u_1) - u_1 \right)$$
3.  $$y_n = u_1 + u_2$$
4.  $$s_n = u_2 + \text{round}\left( D_{2D}(y_n) - y_n \right)$$

### 2.2 Адваротнае блокава-лесвічнае пераўтварэнне (Дэкодэр)
Для кожнага блока $n = K-1, \dots, 0$:
1.  $$u_2 = s_n - \text{round}\left( D_{2D}(y_n) - y_n \right)$$
2.  $$u_1 = y_n - u_2$$
3.  $$s_{n-1} = u_2 - \text{round}\left( C_{2D}(u_1) - u_1 \right)$$
4.  $$x_n = u_1 + \text{round}\left( D_{2D}(s_{n-1}) \right)$$

## 3. Параметры арыфметыкі з фіксаванай коскай

Дзеля забеспячэння поўнай ідэнтычнасці праграмнай мадэлі і апаратнага блока выкарыстоўваецца **12-бітная арыфметыка з фіксаванай коскай (фармат Q1.10)**:
*   **Даўжыня слова:** 12 біт (1 знакавы біт, 1 біт цэлай часткі, 10 біт дробнай часткі).
*   **Рэжым акруглення:** Акругленне да найбліжэйшага цотнага (Convergent Rounding / `AP_RND_CONV`).
*   **Рэжым перапаўнення:** Усячэнне (`AP_TRN`).
*   **Акумулятар:** Пры множанні матрыц выкарыстоўваюцца 32-бітныя зменныя для папярэджання прамежкавага перапаўнення.

## 4. Інструкцыя па запуску прыкладання

### 4.1 Праграмная мадэль (Python)
Рэалізацыя на Python змяшчае CLI-прыкладанне для запуска і юніт-тэсты.

#### Падрыхтоўка асяроддзя
Упэўніцеся, што віртуальнае асяроддзе актывавана, і ўсталюйце залежнасці:
```bash
pip install -r requirements.txt
```

#### Запуск CLI-ацэнкі
Скрыпт запускае сістэму L2L на выяве, параўноўвае рэжымы без страт (з SIB) і са стратамі (без SIB), выводзіць метрыкі якасці і захоўвае рэканструяваныя выявы ў каталог `data/output/`.

1.  **Запуск са стандартным ДКП на сінтэтычнай выяве:**
    ```bash
    python scripts/run_lab3.py
    ```
2.  **Запуск з уласнай выявай:**
    ```bash
    python scripts/run_lab3.py --image шлях/да/выявы.png
    ```
3.  **Запуск з выкарыстаннем хуткага ядра Лёфлера (Loeffler DCT):**
    ```bash
    python scripts/run_lab3.py --use-loeffler
    ```

#### Запуск юніт-тэстаў
Для праверкі абарачальнасці пераўтварэнняў і аднаўлення без страт выканайце:
```bash
pytest tests/test_lab3.py -v
```

### 4.2 Апаратны block AMD Vivado / Vitis HLS
Праверка апаратнай архітэктуры ажыццяўляецца праз C-Simulation тэстбэнч з дапамогай тэставых вектараў.

#### 1. Генерацыя тэставых вектараў
Запусціце скрыпт для стварэння біт-дакладных уваходных/выхадных вектараў (выкарыстоўваюцца зменшаныя значэнні Q1.10, каб пазбегнуць перапаўнення `ap_fixed<12, 2>`):
```bash
python scripts/generate_tb_vectors.py
```
Вектары будуць запісаны ў файл [tb_vectors.txt](file:///d:/Labs/master/image_processing/hardware/src/tb_vectors.txt).

#### 2. Запуск сінтэзу і верыфікацыі HLS
Адкрыйце камандны радок Vivado HLS (ці кансоль Vitis HLS) і запусціце Tcl-скрыпт:
```bash
vivado_hls -f hardware/scripts/hls_script.tcl
```
або ў Vitis HLS:
```bash
vitis_hls -f hardware/scripts/hls_script.tcl
```

Гэты скрыпт выканае наступныя крокі:
1.  Ініцыялізуе праект `l2l_hls_project`.
2.  Дадасць апаратныя файлы і тэстбэнч.
3.  **C Simulation (`csim_design`):** Кампілюе і запускае C++ тэстбэнч у [l2l_tb.cpp](file:///d:/Labs/master/image_processing/hardware/src/l2l_tb.cpp) для праверкі адпаведнасці вектарам з Python.
4.  **C Synthesis (`csynth_design`):** Генеруе RTL-код (Verilog/VHDL) і справаздачы аб часовых затрымках.
5.  **C/RTL Co-Simulation (`cosim_design`):** Запускае дынамічнае мадэляванне сінтэзаванага блока ў сімулятары.
6.  **Export IP (`export_design`):** Экспартуе гатовы блок як IP Core для выкарыстання ў Vivado IP Integrator.
